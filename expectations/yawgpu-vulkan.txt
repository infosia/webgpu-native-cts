# F-111: external_texture render pipeline on yawgpu Vulkan — yawgpu deterministically rejects
# external textures on the Vulkan backend (Metal-only posture, mirroring wgpu), so this case
# (which expects pipeline creation to SUCCEED, as Dawn does) fails. Background: Tint's SPIR-V
# writer DOES lower `texture_external` (the old naga backend could not), but whether a driver
# accepts the multiplanar SPIR-V is GPU-DIVERGENT — native NVIDIA compiles it, Mesa rejects it,
# MoltenVK fails SPIR-V->MSL on the argument-buffer base type. Rather than ship that divergence,
# yawgpu detects the external-texture binding in select_{render,compute}_shader_source and returns
# a clean GPUInternalError BEFORE any SPIR-V reaches a driver (device-independent; commit 0985538).
# A real Vulkan re-home would require wiring the multiplanar plane/params bindings on the Vulkan
# HAL, not just relying on driver acceptance. Drop these entries if/when that lands.
# See specs/blocks/36-external-textures.md (R9) + memory f060-external-textures.
webgpu:api,validation,render_pipeline,misc:external_texture:isAsync=false
webgpu:api,validation,render_pipeline,misc:external_texture:isAsync=true

# F-139: depth_clip_clamp under MoltenVK — NOT a yawgpu defect on native Vulkan.
# WebGPU requires shader-written frag_depth to be clamped to the viewport [minDepth,maxDepth]
# range, and (with unclippedDepth=false) out-of-[0,1] primitives to be clipped. yawgpu's Vulkan
# HAL maps this correctly for NATIVE Vulkan: depthClampEnable=true + VK_EXT_depth_clip_enable
# (VkPipelineRasterizationDepthClipStateCreateInfoEXT.depthClipEnable = !unclippedDepth), which on
# a conformant Vulkan driver clamps frag_depth to the viewport range and clips out-of-range geometry.
# MoltenVK does NOT honor this: Metal clamps shader [[depth]] output only to [0,1] (never to the
# viewport sub-range), and MoltenVK collapses depthClampEnable=true to MTLDepthClipMode.Clamp, which
# also defeats the primitive clipping the depth_clamp_and_clip case needs. So these two sub-cases fail
# ONLY through MoltenVK; they pass on real Vulkan hardware. yawgpu's Metal backend passes the same
# CTS cases because it applies an in-shader frag_depth clamp transform (Tint MSL clamp_frag_depth +
# encode_render_frag_depth_clamp); the Vulkan/SPIR-V path has no equivalent because native Vulkan
# does not need one. Per docs/06-build-and-run.md, MoltenVK is non-authoritative Vulkan coverage.
# FOLLOW-UP (optional, for full MoltenVK/Dawn parity): port the in-shader clamp to the SPIR-V path
# (Tint SPIR-V-writer clamp_frag_depth + a push-constant carrying [minDepth,maxDepth] set at render
# encode). Deferred: it is a MoltenVK-only workaround touching every fragment pipeline layout, and
# native Vulkan — the authoritative target — is already correct. See memory f045-frag-depth-clamp.
webgpu:api,operation,rendering,depth_clip_clamp:depth_test_input_clamped:unclippedDepth=false
webgpu:api,operation,rendering,depth_clip_clamp:depth_clamp_and_clip:writeDepth=true
